# The end-to-end stack: how it fits together, with verification as the spine

Drafted 2026-10-04. Companion to `INTEGRATION-MAP-2026-10-04.md` (which says who owns what). This file says how the layers connect at runtime, what each interface carries, and how verification is tuned to this stack's actual needs. Labels: MEASURED (from files or a run), DESIGN (written, not wired), VISION (transcript only).

## 0 · The meta goal: an environment that makes it hard to write bad code

Stated by Luke 2026-10-04. Everything below serves it, and it fixes the order of preference for every door in the stack. A mistake class should be stopped at the *highest* rung it can be; a rung lower is a fallback, not a choice:

| Rung | The door | Who holds it | Cost of a mistake that reaches here |
|---|---|---|---|
| 1 Impossible | Architecture and types: the wrong state is unrepresentable (`TaskState` whitelist transitions; `transition` is the only writer; `decide` the only verdict; typed refusals; no `unsafe`; permission classes as types) | K0 contracts, K1 store | zero — it does not compile |
| 2 Refused at the door | Admission: the brief lacks RESTATEMENT/ACCEPTANCE; the observation has no `input_sha256`; zero files; stale binary (`doctor`); a rule with two enforcing sites; a count literal in prose | admit, `decide`, the one-door census, the scaffold lint | seconds, before any work |
| 3 Caught by a check | Build, tests, plants/mutants, deep-diff-forge rank, feature-map drive | the derived tiered gate | minutes, per commit |
| 4 Caught by review | interrogate / swarm / a human | advisory tier-1 | hours, and only if someone looks |
| 5 Caught in production | the crash drill, receipts, recovery | ledger + R01–R14 | the tail |

Two consequences the rest of this file is bound by:
- **The `correct` ladder is the engine's growth law, not a skill.** When a mistake class recurs, it is moved *up* a rung (review → check → door → type), and the new rung must be proven to fail on the real past instance. The anti-pattern register AP-01…50 is therefore a backlog of mistakes still sitting at rung 3–4; each is a candidate to move up. The number printed at every cut is `rungs = {1:n,2:n,3:n,4:n,5:n}` for the classes on record — the goal is mass moving upward.
- **Review is the floor, not the gate.** Anything that only a reviewer catches is, by definition, still easy to write. Tier-1 stays advisory for that reason: a verdict that depends on a reader is a rung-4 door wearing a rung-3 badge.

What "bad code" means here, measured not felt: a change that (a) makes a state the types allowed but the design forbids, (b) passes a gate that looked at nothing, (c) carries a claim without its evidence label, (d) adds a second home or a second door for an existing rule, (e) leaves an interrupted task in a non-terminal state. Each has a rung-2 or rung-1 door in this map; none relies on rung 4.

## 3 · Verification, tuned to this stack

What this stack actually is: one machine, one owner, a local model in the loop, runs that must be able to proceed unattended (mode `auto`) and must survive a crash. Verification has to be shaped by that, not copied from a team workflow. Seven tunings:

1. **Deterministic decides; models advise.** Only tier-0 observations (build, tests, lints, deep-diff-forge rank, feature-map drive, plants) feed the verdict lattice. Tier-1 (interrogate, swarm, arena, any Jev score) are observations with `advisory: true`; `decide` may refuse on them, never PASS because of them. (pstack "prove it works: do not infer from proxies, self-reports or 'it compiles'"; HEE AP-01, judge-admission "advice is never authority".)
2. **Bind every observation to its subject.** `head_sha` and `input_sha256` are mandatory fields; the gate runs on a `git archive` export at a sha, never the live worktree (REQUIREMENTS rank 6). A verdict is keyed to the sha it judged (pstack autopilot: "clean root swarm verdict at a matching patch-id").
3. **Refuse to look at nothing.** Zero files, zero tests collected, zero features driven → the observation is refused, not green (AP-29; swarm "a gap is never a pass"). deep-diff-forge `--require-files --require-hunks` is the first concrete door.
4. **Doctor first.** Every feature-map drive starts with `doctor` on a fresh instance (unit active, socket perms, ledger opens, model reachable, binary = the sha under test). "A result against a stale binary is not evidence."
5. **Observations are durable before the verdict.** Each observation is written to the ledger as it arrives; `decide` reads from the ledger, not from memory. After `kill -9`, recovery replays observations and either re-decides or marks the task for a named quarantine — never `effect_unknown` with only a manual exit (gap found 2026-10-04 review).
6. **Tiers are derived from cost, and printed.** commit / stack / cut tiers declared once in `gate.toml`; each step prints `elapsed/budget` and `margin=`; no count literals anywhere in prose (REQUIREMENTS ranks 1, 6; AP-28).
7. **Verification grows only by the correct ladder.** No new check is admitted unless it fails on a real past mistake (I6). The anti-pattern register (AP-01…50) is the backlog of candidate doors; each detector carries the admission header (trigger, budget, reader) — D-04, currently `headerless=all`.

Evidence labels everywhere: every claim in a receipt, a card, a brief or a reply is MEASURED, INFERRED or UNMEASURED (HEE FACT/INTERP/UNMEASURED ≡ pstack measured/inferred/guess).

## 4 · One task, end to end (the walking skeleton, with the integrations attached)

1. A backlog row becomes an order (I2) → `task.submit` with a 9-field brief (I1). Mode dial checked: `manual` = refuse unless Luke's word; `supervised` = admit, hold settle; `auto` = proceed.
2. `route` picks the model by capability floor; a typed refusal if none qualifies (LoomLattice `ll-router` idea, as one HEE rule).
3. A candidate namespace (bwrap) is planned and spawned through the spawn door; the local model is driven inside it; the playbook's steps are the todolist, skipped steps carry `skip: <reason>`.
4. Observations arrive and are ledgered (I3): build, tests, lints, `deep-diff-forge --rank --json --require-files --require-hunks` (sealed), feature-map drive after `doctor`, plants.
5. `decide` runs the fail-closed lattice over identities + observations; Decision+Observed sealed; receipt chained (I4); ledger verdict = `verdict_of(decide)`.
6. Settle: accept into main or repair; `events.subscribe` carries it to the floor (I5). `/reflect` writes the lesson to `brain/`; a repeated lesson goes up the correct ladder (I6).
7. Drill: `kill -9` the unit mid-step-4; restart; recovery replays the ledger; the task ends terminal or quarantined — the D7 criterion, strengthened.
